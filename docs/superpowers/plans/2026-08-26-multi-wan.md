# Multi-WAN Visibility Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Enrich Network WAN with ready / feature flags / virtWanGroups / last-test from fw-app init — read-only, no UI redesign, no write handlers.

**Architecture:** Extend `ParseInitObservatory` to capture `runtimeFeatures`, `wanTestResult`, and virt `failback`/`strictVPN`. Attach additive fields on `GET /v1/network` by peeking `ObservatorySnapshot` (same pattern as other observatory facades). NetworkTab gains quiet chips + one dashed strip. `capabilities.writes` is always `false`.

**Tech Stack:** Go (fwapp parse + api), React/TypeScript (NetworkTab), hermetic JSON testdata under `server/internal/fwapp/testdata/`.

**Spec:** `docs/superpowers/specs/2026-08-26-multi-wan-design.md`

```go
// multiWANNetworkExtras returns omitempty-friendly map keys for GET /v1/network.
func multiWANNetworkExtras(snap fwapp.ObservatorySnapshot, ok bool) map[string]any {
	out := map[string]any{
		"capabilities": map[string]any{"writes": false},
	}
	if !ok {
		return out
	}
	if snap.WanFeatures != nil {
		out["features"] = snap.WanFeatures
	}
	if snap.WanTest != nil {
		out["wan_test"] = snap.WanTest
	}
	if len(snap.VirtWANs) > 0 {
		out["virt_wans"] = snap.VirtWANs
	}
	return out
}
```

Also assert helper with non-nil `WanTest` includes `wan_test.wans.eth1` in the map (populated serialization). Put helper tests in `api_network_wan_test.go` with `package api` (not `api_test`) so the unexported helper is reachable.
